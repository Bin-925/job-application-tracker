# ADR 0001: 핵심 사용 흐름과 PWA 기반

- 날짜: 2026-09-23
- 상태: 이번 로컬 개발 버전에 적용
- 목표: 실사용 가능한 지원/일정 관리와 선택 이유를 설명할 수 있는 포트폴리오

## 선택과 이유

| 선택 | 현재 해결하는 문제 | 대안과 재검토 조건 |
| --- | --- | --- |
| Java 21 + 기존 Spring Boot | 이미 구현된 인증/JPA/검증/테스트를 살리고 일정 저장의 원자성을 트랜잭션으로 다룬다. | Kotlin/Node 재작성은 이번 문제를 더 잘 해결한다는 근거가 없어 하지 않는다. |
| React + 기존 JavaScript | 기존 UI와 API 사용 코드를 이해할 수 있는 언어를 유지하고 먼저 실제 흐름을 검증한다. | TypeScript는 계약이 커질 때 점진 도입한다. 이번 단계에 언어 전환까지 동시에 넣지 않는다. |
| React Router URL 필터 | 홈에서 특정 목록으로 이동하고 새로고침/뒤로가기로 같은 조건을 재현한다. | 컴포넌트 state만 쓰면 링크를 공유하거나 복원하기 어렵다. |
| 별도 ScheduleEvent | 1차/2차 면접과 과제 마감, 완료/취소를 각각 기록한다. | Application에 interview2Date 등 칼럼을 계속 추가하지 않는다. |
| JPA 버전 + 409 | 두 화면의 일정/지원 편집이 최신 내용을 조용히 덮어쓰지 않게 한다. | 사용자가 충돌을 해결할 UI가 복잡해지면 필드별 병합을 검토한다. |
| date-fns | 월의 시작/끝, 주 단위 경계, 날짜 포맷을 라이브러리에 맡긴다. | 달력 UI는 제품 흐름에 맞춰 구성하되 날짜 연산을 직접 구현하지 않는다. |
| CSS custom properties | 라이트/다크 색과 간격을 한곳에서 관리한다. | 새 화면에서 쓰지 않는 Tailwind 의존성은 제거했다. 둘을 장식적으로 함께 두지 않는다. |
| Lucide | 상태/일정/탐색/편집 아이콘의 의미와 크기를 통일한다. | 표준 아이콘을 임의 SVG로 다시 그리지 않는다. |
| vite-plugin-pwa + Workbox | manifest와 정적 파일 캐시, 버전 교체 알림을 빌드와 함께 관리한다. | 서비스 워커 수명주기를 직접 구현하는 비용을 피한다. |
| NetworkOnly API | 취업 기록/인증 응답이 공유 브라우저의 장기 캐시에 남는 것을 피한다. | 오프라인 개인 데이터가 꼭 필요하다는 사용 근거가 생기면 암호화/계정 분리/삭제 정책부터 설계한다. |
| sharp (개발 도구) | 같은 Lucide 브랜드 원본에서 필요한 크기의 PNG 설치 아이콘을 재생성한다. | 런타임에 포함하지 않는다. |
| Node test + JUnit/MockMvc | 집계 경계와 소유권/트랜잭션을 각각 알맞은 수준에서 검증한다. | 더 복잡한 화면 상호작용에는 컴포넌트/E2E 자동 테스트를 추가한다. |
| H2 demo 프로파일 | 이 PC에서 운영 DB 연결 없이 실제 API 저장을 체험한다. | 운영 DB 대안으로 선택한 것이 아니다. PostgreSQL 호환성 검증을 따로 해야 한다. |

## 왜 앱으로 배포하는가

취업 준비 중 반복해서 일정과 진행 상태를 확인하는 사용 흐름이 있다.
브라우저 탭을 찾아 들어가는 마찰을 줄이기 위해 설치 가능한 PWA를 먼저 검증한다.
현재 웹 코드와 배포 경로를 재사용하면서 홈 화면 진입과 독립 창 실행을 제공하는 것이 목적이다.
설치 자체가 서비스의 가치를 만들지는 않으므로 핵심 CRUD와 일정 정확성이 선행 조건이다.

원스토어는 Android 사용자가 앱을 발견하고 설치하는 배포 채널 후보이다.
지금 단계에서 별도 네이티브 앱을 병행하지 않는다. PWA 사용성과 설치 수요를 확인한 뒤,
TWA의 제약과 실제 원스토어 서명/심사 요건을 확인하고 패키징 방식을 확정한다.
푸시 알림, 백그라운드 동작, 네이티브 기능이 필요하다는 이유만으로 TWA가 이를 모두 해결한다고 가정하지 않는다.

## 의도적으로 미룬 기술

EC2, Redis, 메시지 큐, 마이크로서비스, 별도 모바일 프레임워크는 도입하지 않았다.
실제 운영량, 반복되는 장애, 비용 측정, 네이티브 기능 요구로 설명할 수 있을 때 검토한다.
인증 저장 방식과 DB 마이그레이션은 출시 전 필수 작업이며, 미뤘다는 사실을 출시 준비 완료로 포장하지 않는다.

## 비용과 한계

현재 지원 목록은 사용자 단위 전체 조회/클라이언트 필터다.
홈과 목록의 일관성이 단순해지는 대신 지원 수가 커지면 전송량과 렌더 비용이 증가한다.
실제 사용자 데이터 크기를 측정해 서버 필터/페이지네이션으로 옮길 시점을 결정한다.
지원/일정 타입과 시간 기준을 공유 함수와 테스트로 먼저 고정했다.
