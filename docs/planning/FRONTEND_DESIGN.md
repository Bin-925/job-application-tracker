# 취준노트 프론트엔드 디자인

작성일: 2026-09-23. 사용자가 프론트 디자인 판단을 위임했다. 제품 목표는 실사용 완성도와 취업 포트폴리오, PWA 및 원스토어 출시다. 이 문서는 구현 전 디자인 기준이며 동작하는 화면의 검증 결과가 아니다.

## 1. 선택한 방향

오늘 할 일을 먼저 보여주는 차분한 업무 도구로 설계한다. 여러 지원의 비교는 별도 목록에서, 날짜 탐색은 월간 캘린더에서 처리한다. 홈의 진행 중/면접 예정 숫자는 필터된 지원 목록으로 연결되는 두 개의 작은 요약 박스로 제공한다.

세 가지 시각 구성을 비교한 뒤 오늘 중심 홈을 기본안으로 선택했다. 이후 사용자가 월간 캘린더와 클릭 가능한 진행 중/면접 예정 박스를 요청해 최신 시안에 반영했다. 최초 주간 일정과 인라인 통계 시안은 과거 탐색안이며 현재 구현 기준이 아니다.

| 시안 | 활용 | 선택 이유 |
|---|---|---|
| [오늘과 요약 박스](design/today-summary-concept.png) | 기본 진입 화면 | 오늘 일정 확인 및 관심 지원 목록으로 바로 이동 |
| [지원 목록](design/applications-concept.png) | 지원 탭 | 회사/직무/상태/다음 일정을 빠르게 비교 |
| [월간 캘린더](design/month-calendar-concept.png) | 일정 탭 | 한 달 일정 분포를 보고 날짜를 선택해 해당 일정 확인 |

시안은 built-in Image Gen으로 생성한 참고 이미지다. 실제 폰트 크기, 클릭 영역, 문구, 데이터 정합성은 구현 규격을 따른다. 회사명/일정은 가상 데이터이며 사용자 기록이 아니다. 생성 프롬프트는 [IMAGE_PROMPTS.md](design/IMAGE_PROMPTS.md)에 보관했다.

## 2. 화면과 탐색

하단 탐색은 `오늘 / 지원 / 일정 / 내 정보` 네 개로 통일한다. 기존 세 개 탐색에서 지원 목록을 분리하는 이유는 오늘 할 일과 전체 기록을 서로 다른 목적의 화면으로 만들기 위해서다.

| 화면 | 배치와 핵심 동작 |
|---|---|
| 오늘 `/` | 날짜 -> 클릭 가능한 진행 중/면접 예정 박스 2개 -> 오늘 일정 -> 가까운 일정. 박스는 필터된 지원 목록, 일정 행은 해당 지원 상세로 이동 |
| 지원 `/applications` | 회사·직무 검색 -> 전체/진행 중/면접 예정 빠른 필터 -> 개별 상태/정렬 -> 목록. 선택 필터를 URL에 반영하고 상세에서 돌아오면 스크롤/검색/필터 유지 |
| 일정 `/calendar` | 월간 보기, 이전 달/다음 달/오늘 버튼, 날짜 선택, 선택한 날짜의 일정 목록. 첫 출시에서 주간 전환은 제공하지 않음 |
| 지원 상세 `/applications/:id` | 회사·직무·현재 상태 -> 예정 일정 -> 기본 정보·공고 링크 -> 메모 -> 완료/취소된 일정. 편집 버튼과 추가 일정 동작 |
| 지원 등록 `/applications/new` | 회사·직무 필수, 상태 기본 지원예정. 날짜/공고 링크/메모는 선택. 한 페이지의 간결한 폼 |
| 지원 편집 `/applications/:id/edit` | 현재 지원 정보를 수정. 일정 편집과 분리해 오래된 전체 객체로 다른 기기 변경을 덮어쓰지 않음 |
| 일정 편집 | 모바일 별도 화면, 넓은 화면 우측 패널. 종류·면접 구분·날짜·시간 미정·알림 여부. 키보드가 열린 상태에서도 저장 가능 |
| 알림 `/notifications` | 가까운 일정 안내와 현재 기기 알림 상태. 아직 없는 발송 이력/읽음 API를 임의로 가정하지 않음 |
| 내 정보 `/mypage` | 프로필, 기기 알림, 테마, 계정 설정, 로그아웃. 회원 탈퇴는 계정 설정 안에 배치 |

고정 하단 탐색은 주요 네 화면에만 보인다. 등록/편집에서는 뒤로가기와 저장 행동에 집중한다. 추가 버튼은 오늘/지원에서는 지원 등록, 일정 탭에서는 '연결할 지원 선택 -> 일정 등록'으로 동작하며 접근 가능한 이름을 문맥에 맞게 준다.

### 홈 요약 박스와 목록의 연결

| 박스/필터 | 집계와 목록 조건 | 이동 경로 |
|---|---|---|
| 진행 중 | 상태가 APPLIED/DOC_PASSED/INTERVIEW인 지원 건 | `/applications?view=in-progress` |
| 면접 예정 | 진행 중인 지원 중 완료/취소되지 않은 미래 면접 일정이 하나 이상 있는 지원 건 | `/applications?view=upcoming-interviews` |

- 두 박스 모두 숫자의 단위는 지원 건이다. 하나의 지원에 면접 두 개가 있어도 면접 예정 박스와 지원 목록에서는 1건이다. 기존 초안의 '면접 이벤트 수' 집계를 대체한다.
- 미래 판단은 서버의 Asia/Seoul 기준이다. 시간이 있으면 현재 시각 이후, 시간 미정이면 오늘을 포함한 이후 날짜를 대상으로 한다. 지났거나 취소/완료된 면접 및 종료/철회한 지원은 제외한다.
- 면접 예정은 진행 중의 부분집합이다. 두 숫자를 합쳐 전체 지원 수로 표시하지 않는다.
- 진행 중 박스는 최근 수정순, 면접 예정 박스는 지원별 가장 가까운 유효 면접순으로 연결한다. 같은 날짜의 시간 미정은 시각이 정해진 면접 뒤에 표시한다.
- 홈에서 진입할 때 과거 검색어/개별 상태 조건을 함께 가져오지 않는다. 새 필터만 적용해 박스 숫자의 의미가 유지되게 한다. 직접 링크/새로고침/뒤로가기도 같은 필터 상태를 복원한다.
- 지원 탭의 빠른 필터는 전체/진행 중/면접 예정이다. 개별 상태 필터는 빠른 필터 안에서 추가로 좁히며 화면에 조건을 표시한다. 전체로 돌아가는 동작을 제공한다.
- 0건도 박스를 비활성화하지 않는다. 이동 후 해당 조건에 맞는 빈 상태를 보여준다. 로딩/실패를 0으로 바꾸지 않는다.
- 집계와 목록에 같은 도메인 조건을 사용한다. 조회 사이 기록 변경이나 시간이 경과하면 숫자는 달라질 수 있으므로 최신 목록 건수를 표시하고 복귀 시 집계를 갱신한다.
- 박스 전체를 실제 링크로 구현한다. label/숫자/작은 chevron을 배치하고 키보드 focus를 제공한다. 내부에 별도 버튼을 중첩하지 않는다.

## 3. 시각 규칙

| 항목 | 기본값 |
|---|---|
| 기본 배경/텍스트 | `#FFFFFF` / `#20252B` |
| 보조 표면/텍스트 | `#F5F6F8` / `#59636E` |
| 주요 행동/현재 탭 | `#245BD7` |
| 면접/긍정 상태 | `#147D57` |
| 마감/주의 | `#8A5700` |
| 구분선 | `#E1E5E9` |
| 파괴적 행동 | 붉은 텍스트와 명확한 문구. 빈번한 주 행동과 떨어뜨림 |
| 서체 | 기존 시스템 sans-serif 계열, 한국어는 기기 기본 글꼴 활용. 새 웹폰트 다운로드를 필수로 만들지 않음 |
| 글자 크기 | 본문/입력 16px, 보조 14px, 탐색 12px, 섹션 18px, 페이지 제목 24px, 줄간격 1.4~1.6 |
| 자간 | 0. 화면 너비에 비례해 글자를 줄이지 않음 |
| 간격 | 4/8/12/16/24/32px 단계. 모바일 좌우 16px, 넓은 화면 24~32px |
| 모서리 | 폼/메뉴/모달 6~8px. 원형 추가 버튼/날짜 선택만 원형 |
| 아이콘 | 구현 시 lucide-react로 통일. 도구 버튼은 익숙한 아이콘+접근 가능한 이름, PC에서는 tooltip |

주요 색상의 흰 배경 대비를 수식으로 확인했다: 파랑 5.91:1, 초록 5.12:1, 황갈색 6.10:1, 보조 텍스트 6.11:1, 본문 15.43:1. 이는 지정한 색상 조합의 계산이며 생성 이미지나 실제 화면 전체의 접근성 검증 결과는 아니다.

상태는 `점 + 상태 이름`으로 표시하고 색만으로 구별하지 않는다. 지원예정/불합격/철회는 중립 색, 지원완료는 파랑, 서류합격은 황갈색, 면접/최종합격은 초록을 기본으로 하되 글자로 의미를 구분한다. 일정의 면접은 항상 초록, 마감은 항상 황갈색이다. 오늘 시안에서 내일 면접이 파란색으로 표현된 부분은 구현 시 초록으로 바로잡는다.

홈 요약 박스는 나란한 2열, 간격 12px, 모서리 8px, 기본 최소 높이 84px로 구성한다. 글자 확대 시 높이가 늘어나도록 허용한다. 박스 안 박스와 장식용 배경은 쓰지 않는다. 일정/지원 목록은 같은 표면의 행과 구분선으로 구성한다. hover나 로딩에 따라 크기가 흔들리지 않게 한다.

다크 모드는 기존 기능을 유지한다. 중립 배경 `#151719`, 표면 `#202326`, 본문 `#F3F4F6`, 보조 `#B6BEC8`를 출발점으로 하고 강조색은 별도 밝은 토큰으로 맞춘다. 다크 화면의 대비와 상태 구분은 실제 구현에서 따로 검증한다. 기본 테마는 시스템 설정을 따르되 사용자가 선택하면 유지한다.

## 4. 모바일과 PC

- 모바일: 360~599 CSS px를 기본 범위로 설계한다. S25 Ultra의 물리 해상도를 CSS viewport로 가정하지 않고 실기기 viewport/글자 배율을 측정한다.
- 중간 화면: 600~1023px에서는 읽을 영역을 넓히되 목록과 편집 화면을 한 열로 유지할 수 있다.
- 넓은 화면: 1024px 이상에서 고정 폭 약 200px 탐색과 유연한 본문을 사용한다. 지원 화면은 최소 360px 목록과 최소 400px 상세가 들어갈 때 두 열로 전환한다.
- PC 전체에 휴대폰 프레임을 씌우지 않는다. 상세 선택은 URL에 반영해 새로고침·뒤로가기·공유가 가능하도록 한다.
- 터치 대상은 최소 44x44px, 주요 저장/등록은 높이 48px 이상을 목표로 한다. 시각적인 아이콘이 작더라도 실제 클릭 영역은 유지한다.
- 하단 탐색은 safe-area를 고려하고, 본문 바닥 여백에 탐색 높이와 추가 버튼 공간을 포함한다. 마지막 목록을 가리지 않는다.
- 긴 회사명은 목록에서 최대 두 줄, 상세에서 전체 표시한다. 오른쪽 상태/날짜 때문에 회사명이 읽을 수 없게 되면 좁은 화면에서 세로 배치로 바꾼다.
- 달력은 일요일 시작의 안정된 7열 월간 grid다. 한 달의 실제 주 수에 맞춰 행을 표시하고 6주 달도 화면이 겹치지 않게 설계한다. 날짜 클릭 대상 높이는 최소 44px로 한다.
- 오늘과 선택일은 각각 테두리/배경으로 구분한다. 일정은 날짜 아래 면접/마감 표시와 접근 가능한 이름으로 안내한다. 많은 이벤트를 셀 안에 넣지 않고 선택한 날짜의 목록에서 보여준다.
- 최초 진입은 오늘 선택이다. 다른 달로 이동하면 그달 1일을 선택하고, 오늘 버튼은 현재 월/오늘로 돌아온다. 선택 날짜와 표시 월은 URL에 보존한다. 다른 달 날짜를 누르면 해당 월로 이동한다.

## 5. 입력과 중요한 상태

| 상황 | 보여줄 내용과 행동 |
|---|---|
| 처음 사용 | '아직 등록한 지원이 없어요'와 첫 지원 등록. 실제 기록처럼 보이는 데모 데이터 자동 생성 금지 |
| 오늘 일정 없음 | '오늘 예정된 일정이 없어요'와 가까운 일정. 오류와 구분 |
| 검색 결과 없음 | 검색 조건과 결과 없음, 검색 지우기 동작 |
| 통신 실패 | '지원 기록을 불러오지 못했어요' + 다시 시도. 0건으로 바꾸지 않음 |
| 로그인 만료 | 재로그인 안내, 내부 복귀 경로 유지. 입력 중인 폼은 가능한 범위에서 보존하되 계정 전환에 노출하지 않음 |
| 저장 중 | 저장 버튼의 폭 유지, 중복 요청 방지, 입력 내용은 화면에 유지 |
| 저장 실패 | 오류와 재시도, 폼 유지. 성공한 것처럼 상세로 돌아가지 않음 |
| 수정 충돌 409 | '다른 곳에서 수정된 기록입니다'와 최신 내용 확인. 기존 입력을 바로 버리거나 자동 덮어쓰지 않음 |
| 시간 미정 | checkbox/toggle로 명시. 시간 미정일 때 입력 비활성 및 null 전송. 자정으로 표시하지 않음 |
| 알림 거절/미지원 | 저장 기능은 정상 제공. 권한 상태와 실제 가능한 다음 행동을 보여줌 |
| 오프라인 | 연결 안내와 재시도. 첫 출시에서는 저장 성공이나 최신 일정 조회를 가장하지 않음 |
| 새 버전 있음 | 적용 버튼, 편집 중이면 먼저 저장/나가기 판단. 자동 새로고침 금지 |
| 삭제/탈퇴 | 대상과 삭제 범위 명시. 탈퇴는 비밀번호 재확인과 실수 방지 확인, 완료 후 인증/개인 화면 정리 |

문구 수정: 오늘 시안의 '지원 기록' 버튼은 '지원 완료로 변경'처럼 수행할 동작이 분명하도록 한다. 입력된 날짜가 실제 마감 시각인지 모르면 '오늘 마감 · 시간 미정'으로 표시한다. 데이터 모델이 제공하지 않는 면접 장소/후기 필드를 디자인만으로 필수 기능에 추가하지 않는다.

가입/로그인은 한 열 폼, 보이는 label, 비밀번호 표시 전환, 제출 오류와 비밀번호 확인 불일치를 제공한다. 네이티브 날짜 입력의 동작을 S25 Ultra에서 먼저 확인하며 필요성이 확인되지 않은 커스텀 날짜 선택기를 만들지 않는다.

## 6. 컴포넌트와 구현 순서

공통 단위는 `AppShell`, `BottomNavigation`, `SideNavigation`, `PageHeader`, `IconButton`, `ApplicationRow`, `ScheduleRow`, `StatusLabel`, `FormField`, `AsyncState`, `ConfirmDialog`, `UpdateNotice`로 제안한다. 실제 재사용이 생길 때 추출하고, 한 화면의 고유 동작까지 범용 설정 객체에 넣지 않는다.

기존 API/controller 작업 순서와 맞춰 홈 오류 상태 -> 지원 목록/상세 -> 등록/편집 -> 일정 -> 알림/계정 -> 설치/업데이트 경험으로 구현한다. TypeScript는 새 도메인/API와 수정하는 컴포넌트부터 적용한다. 전체 디자인 구현을 제품 안정화보다 먼저 완결해야 하는 별도 대형 작업으로 만들지 않는다.

UI 개발 전 작은 화면과 넓은 화면의 구현 목표를 정하고, UI 개발 후 실제 screenshot으로 확인한다. 생성 이미지를 그대로 배경으로 붙여 화면을 구현하지 않는다. 접근 가능한 실제 HTML과 작동하는 입력/탐색으로 구성한다.

## 7. 검증 기준

- 360/390/412/768/1280/1440px에서 긴 회사명, 긴 직무명, 오류 문구, 데이터 없음/많음을 확인한다.
- 글자 확대, 키보드만의 탐색, 보이는 focus, 버튼 이름, 폼 오류 연결을 확인한다. 모달은 focus 진입/복귀와 Esc를 처리한다.
- 날짜와 시간은 Asia/Seoul 정책을 따르고, 날짜만 있는 값과 실제 시각을 혼동하지 않는다.
- 계정 전환과 로그아웃 후 이전 기록이 화면/메모리 상태에 남지 않는지 확인한다.
- S25 Ultra에서 소프트 키보드, 하단 safe-area, 뒤로가기, 설치된 PWA, TWA 외부 링크를 검증한다.
- 정렬/필터/상태/날짜가 바뀌어도 버튼과 행이 예측 불가능하게 이동하지 않는지 확인한다.
- 각 요약 박스 클릭, 0건, URL 직접 진입, 새로고침, 상세에서 뒤로가기, 필터 초기화를 확인한다. 동일 기준 시각과 데이터에서 집계 수가 필터 목록의 고유 지원 건수와 같아야 한다.
- 한 지원에 미래 면접 두 개, 과거 면접만 있는 지원, 오늘 시간 미정 면접, 완료/취소/종료된 지원을 포함해 면접 예정 필터를 검증한다. 월간 달력은 윤년 2월, 6주 달, 연도 경계 이동을 확인한다.

현재 완료된 것은 초기 시안 세 개와 수정 시안 두 개, 디자인/상태/반응형 명세다. 최신 기준은 요약 박스 홈과 월간 캘린더다. 기존 지원 목록 시안의 '면접' 필터 문구는 구현 시 '면접 예정'으로 맞춘다. 데스크톱/다크 시안과 실제 앱 UI 구현/실기기 검증은 후속 작업이다.
